# Беклог бэкенда: ОМА Лаб

Прототип · NestJS, Prisma, PostgreSQL · P0 нужно для демо, P1 если останется время

## 1. Принципы продукта

- Регистрации нет. При первом заходе создаётся анонимный пользователь. Токен хранится на клиенте и передаётся в заголовке `Authorization: Bearer <token>`.
- Родитель и ребёнок независимы, связи между пользователями нет. Для набора «с родителем» клиент перед стартом урока передаёт флаг «рядом взрослый». Проверок личности нет.
- Оплаты в приложении нет. Набор покупают в магазине или на oma.by, поэтому у набора есть `buyUrl`, а магазины показываются на карте.
- Урок это инструкция из шагов. Пройденным его отмечает сам пользователь кнопкой «Завершено» на последнем шаге. Награды: звезда за урок, значок навыка за ключевой урок.
- Формат ошибки: `{ "code": "CODE_ALREADY_USED", "message": "..." }`. Коды ошибок перечислены в описании фич.

## 2. Модель данных (Prisma)

| Модель | Поля |
| --- | --- |
| User | id, name?, age?, stars (по умолчанию 0), createdAt |
| Kit | id, slug (уникальный), title, description, minAge, mode (`SOLO` или `PARENT`), tool, difficulty (1–3), buyUrl, coverUrl? |
| KitCode | id, code (уникальный), kitId, userId? (кто активировал), activatedAt? |
| Lesson | id, kitId, order, title, skillId? |
| LessonStep | id, lessonId, order, text, imageUrl?, videoUrl? |
| LessonProgress | id, userId, lessonId, status (`IN_PROGRESS` или `DONE`), adultConfirmedAt?, startedAt, completedAt?. Уникальная пара (userId, lessonId) |
| Skill | id, title |
| UserSkill | userId, skillId, earnedAt. Уникальная пара |
| Store | id, name, address, lat, lng, hours |
| StoreKit | storeId, kitId, inStock |
| ChatSession | id, userId, kitId?, lessonId?, createdAt |
| ChatMessage | id, sessionId, role (`USER` или `ASSISTANT`), content, createdAt |

Статус урока для пользователя вычисляется, а не хранится:

- `DONE`: есть прогресс со статусом `DONE`.
- `CURRENT`: первый невыполненный урок по `order`, если набор активирован.
- `LOCKED`: все остальные, а также все уроки неактивированного набора.

## 3. Фичи P0

### B1. Каркас и окружение

**Описание.** Репозиторий NestJS с Prisma и PostgreSQL в docker-compose. Переменные окружения: `DATABASE_URL`, `JWT_SECRET`, `GROQ_API_KEY`, `GROQ_MODEL`, `CORS_ORIGIN`.

**Правила.**

- Глобальный префикс `/api`.
- `ValidationPipe` с whitelist.
- CORS для адреса фронта.
- Единый фильтр ошибок в формате из раздела 1.
- `GET /api/health` отвечает 200.

**Приёмка.** `docker compose up` поднимает БД и API. Миграции применяются одной командой. Health возвращает 200.

### B2. Схема и сид-данные

**Описание.** Миграции по модели из раздела 2 и скрипт `prisma db seed`.

**Данные сида.**

- Набор «Грузовичок» (`truck`): 6+, режим `SOLO`, отвёртка, сложность 1. Уроки: «Знакомство с отвёрткой» (3 шага) и «Закрути винтик» (4 шага, даёт навык «Отвёртка»).
- Набор «Скворечник» (`nest`): 8+, режим `PARENT`, молоток, сложность 2. Уроки: «Держим молоток» (3 шага) и «Забиваем гвоздь» (4 шага, даёт навык «Молоток»).
- Коды: `OMA-TRUCK-001` … `003` и `OMA-NEST-001` … `003`.
- 6 магазинов (Минск и область, условные адреса), в каждом 1–2 набора в наличии.

**Приёмка.** Повторный запуск сида не плодит дубли и не сбрасывает прогресс. В каждом шаге заполнен `text`.

### B3. Сессия и профиль пользователя

**API.**

- `POST /session` возвращает `{ token, user }`.
- `GET /me`.
- `PATCH /me` с телом `{ name, age }`.

**Правила.**

- Токен JWT с `userId`, без срока истечения (для прототипа).
- `name` от 1 до 30 символов, `age` от 3 до 99.
- Гвард защищает все эндпоинты, кроме `/session`, `/health`, `GET /kits`, `GET /kits/:slug` и `/stores*`.

**Ошибки.** 401 `UNAUTHORIZED`, 400 `VALIDATION_ERROR`.

**Приёмка.** Каждый новый вызов `/session` создаёт нового пользователя. `PATCH /me` сохраняет имя и возраст. Запрос без токена к защищённому эндпоинту возвращает 401.

### B4. Наборы

**API.**

- `GET /kits?age=&difficulty=&mode=`.
- `GET /kits/:slug`.
- `GET /kits/:slug/lessons`.

**Ответ по набору.** `id, slug, title, description, minAge, mode, tool, difficulty, buyUrl, coverUrl, lessonsCount`. Если запрос с токеном, добавляются `activated` и `progressPercent`.

**Ответ по урокам.** `id, order, title, status (DONE, CURRENT, LOCKED), skill?`.

**Правила.**

- Фильтры комбинируются через И.
- Параметр `age` возвращает наборы с `minAge <= age`.
- Если набор не активирован, все уроки `LOCKED`.

**Ошибки.** 404 `KIT_NOT_FOUND`.

**Приёмка.** `age=7` не возвращает «Скворечник». Статусы уроков соответствуют прогрессу пользователя.

### B5. Активация набора по коду

**API.**

- `POST /activations` с телом `{ code }` возвращает 201 и `{ kit }`.
- `GET /me/kits`.

**Правила.**

- Код нормализуется (trim, верхний регистр).
- В одной транзакции проверяется, что код свободен, и записываются `userId` и `activatedAt`.
- Один пользователь не может иметь один набор дважды: второй код того же набора возвращает 409, а сам код остаётся свободным.

**Ошибки.** 404 `CODE_NOT_FOUND`, 409 `CODE_ALREADY_USED`, 409 `KIT_ALREADY_OWNED`.

**Приёмка.** Из двух параллельных запросов с одним кодом успешен один. `GET /me/kits` возвращает наборы с `progressPercent`.

### B6. Уроки и прогресс

**API.**

- `GET /lessons/:id`.
- `POST /me/lessons/:id/start` с телом `{ adultConfirmed }`.
- `POST /me/lessons/:id/complete`.

**GET /lessons/:id.** Возвращает урок и шаги по порядку. Ошибки: 403 `LESSON_LOCKED` (набор не активирован или урок закрыт), 404 `LESSON_NOT_FOUND`.

**start.**

- Урок должен быть `CURRENT` или уже начатым.
- Для набора `PARENT` без `adultConfirmed: true` возвращается 400 `ADULT_CONFIRMATION_REQUIRED`. С флагом сохраняется `adultConfirmedAt`.
- Создаётся прогресс `IN_PROGRESS`. Повторный вызов дубль не создаёт.

**complete.**

- Урок должен быть начат, иначе 400 `LESSON_NOT_STARTED`.
- Статус становится `DONE`, к `stars` прибавляется 1, выдаётся навык, если он привязан к уроку.
- Вызов идемпотентен: повторный возвращает 200 с теми же данными, звёзды не начисляются.
- Ответ: `{ stars, skillAwarded?, nextLessonId? }`.

**Приёмка.** После `complete` следующий урок становится `CURRENT`. Повторный `complete` не меняет `stars`. Закрытый урок не отдаётся.

### B7. Профиль и навыки

**API.**

- `GET /me/profile` возвращает `{ name, age, stars, lessonsDone, kits: [{ slug, title, progressPercent, completed }], skills }`.
- `GET /me/skills`.

**Правила.** Набор считается пройденным, когда все его уроки в статусе `DONE`.

**Приёмка.** Данные совпадают с реальным прогрессом сразу после `complete`.

### B8. Магазины

**API.**

- `GET /stores?kit=<slug>&lat=&lng=`.
- `GET /stores/:id`.

**Правила.**

- Фильтр `kit` оставляет магазины, где набор `inStock`.
- Если переданы `lat` и `lng`, добавляется `distanceKm` (формула гаверсинуса) и список сортируется по возрастанию расстояния.
- Ответ: `id, name, address, lat, lng, hours, kits[]`.

**Ошибки.** 404 `STORE_NOT_FOUND`.

**Приёмка.** Фильтр по набору и сортировка по расстоянию работают.

### B9. Чат Омика (Groq)

**API.**

- `POST /chat/sessions` с телом `{ kitId?, lessonId? }` возвращает `{ sessionId }`.
- `POST /chat/sessions/:id/messages` с телом `{ text }` возвращает `{ reply }`.

**Правила.**

- Текст от 1 до 500 символов, иначе 400 `VALIDATION_ERROR`.
- Запрос к Groq через OpenAI-совместимый chat completions API. Модель берётся из `GROQ_MODEL`, `temperature` 0.5, `max_tokens` 300. В контекст идут последние 10 сообщений сессии.
- Системный промпт: Омик дружелюбный помощник детской мастерской ОМА. Он обращается к пользователю по имени и учитывает возраст (для детей до 8 лет отвечает короткими простыми фразами). Отвечает только про текущий набор, урок и безопасность работы с инструментами, на сторонние темы мягко возвращает к уроку. При опасных вопросах просит позвать взрослого. Не выдумывает того, чего нет в инструкции.
- В промпт подставляются имя, возраст, название набора и урока (если сессия к ним привязана).
- Слова опасности (газ, дым, искры, замыкание, ожог) обрабатываются до вызова Groq. Возвращается готовый ответ: «Остановись и позови взрослого. Если опасно, звони 112».
- При ошибке Groq, таймауте (10 секунд) или 429 возвращается 200 с текстом «Омик задумался, спроси ещё раз через минуту». Причина пишется в лог.
- Сообщения пользователя и ответы сохраняются в БД.

**Приёмка.** Ключ Groq не попадает на клиент. Опасный запрос не уходит в Groq. При недоступности Groq приложение не падает.

## 4. Фичи P1

### B10. История чата

`GET /chat/sessions/:id/messages` возвращает сообщения по времени. Сессия доступна только её владельцу (иначе 403).

### B11. Стриминг ответа чата

Эндпоинт `POST /chat/sessions/:id/messages/stream` с `text/event-stream`. События `token` (кусок текста) и `done`. Ошибки Groq обрабатываются так же, как в B9.

### B12. Серверная проверка прохождения

`POST /me/lessons/:id/progress` с телом `{ step }` обновляет `maxStepReached` в `LessonProgress`. `complete` возвращает 400 `LESSON_NOT_FINISHED`, если `maxStepReached` меньше номера последнего шага.

### B14. Код восстановления

`POST /me/recovery-code` создаёт код из 8 символов. `POST /session/restore` с телом `{ code }` возвращает токен прежнего пользователя. Код одноразовый.

### B15. Документация и деплой

Swagger на `/api/docs`, Dockerfile для API, инструкция запуска в README.

## 5. Порядок работ

1. B1, B2, B3.
2. B4, B5, B6, B7 (это ядро, после B5 фронт может переключиться с моков на реальное API).
3. B8 и B9 независимо друг от друга.
4. P1 по остаточному принципу, первыми B12 и B13.

## 6. Сквозная проверка для демо

1. `POST /session`, затем `PATCH /me` с именем и возрастом.
2. `POST /activations` с кодом `OMA-TRUCK-001`, набор появляется в `GET /me/kits`.
3. Старт и завершение первого урока: у пользователя 1 звезда, второй урок становится `CURRENT`.
4. Завершение второго урока: выдан навык «Отвёртка».
5. Активация `OMA-NEST-001`, старт урока без `adultConfirmed` возвращает 400, с флагом проходит.
6. Вопрос Омику возвращает ответ, вопрос про газ возвращает готовый ответ без вызова Groq.
7. `GET /stores?kit=nest` возвращает магазины с набором.
